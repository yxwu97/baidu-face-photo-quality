# 百度离线人脸照片检测工具总体方案

2026 年 11 月 17 日

## 可行性与首版范围

**桌面程序统一使用 Java 和 JavaFX，首版在 Windows x64 交付和验收。** 工具读取 `FaceCapture` 下的抓拍图，逐张判断照片质量，列出实测值、规则阈值和不合格原因。界面、批次、判定、结果库和导出采用跨平台 Java 实现，为后续适配 macOS 保留复用基础。检测引擎按操作系统与 CPU 架构部署，由独立 Java 进程加载。

现有百度 Java 8.4 包包含 Windows 原生 DLL，已确认提供静态图检测、姿态、光照、遮挡和模糊度接口。随包 Java 示例在本机编译通过，JNI 可加载，初始化仍需在目标 Windows 电脑上通过授权。MacBook 作为后续适配平台，本地检测引擎的选型和部署随适配工作确定。 [百度人脸离线识别 SDK 产品页](https://cloud.baidu.com/product/faceSDK) · [JavaFX 21 平台说明](https://openjfx.io/highlights/21/)

首版把“符合要求”定义为**照片适合作为后续人脸识别的输入**，具体以校准后的规则为准。质量合格但历史记录为“未识别”的照片，可用于后续排查。要定位原系统为什么未识别，还需要当时的 SDK、算法配置、活体与比对阈值、对应底库及链路日志。单张 JPEG 只能提供本次质量评估和有限的静态图线索。

## 形态与技术架构

| 形态 | 实现方式 | 适用场景 |
| --- | --- | --- |
| JavaFX 桌面程序 | Java 21、JavaFX 21、SQLite JDBC。界面沿用已确认的三栏原型，业务模块可跨平台复用。首版使用 `jpackage` 在 Windows 构建安装包。 | 在 Windows x64 完成端到端验证。 |
| Windows 检测进程 | 独立 Java 11 x64 进程，通过包内 JNI 调用百度 SDK，与桌面程序经本机标准输入输出交换 UTF-8 JSON 行。 | 在授权 Windows x64 设备上独立离线检测。 |
| macOS 检测进程 | 后续可复用检测协议，按实际 MacBook 架构确认适配的本地引擎与授权。 | 平台扩展。 |
| 本机网页版 | 本机服务可复用 Java 检测进程，网页通过回环地址访问，服务端读取操作者选定目录。 | 后续有浏览器交互需求时使用，检测主机须满足对应引擎的部署与授权条件。 |
| 局域网网页版 | 授权电脑运行检测服务，其他终端访问界面，由服务统一读取共享存储或接收导入文件。 | 适合多人协作，需要明确主机授权、访问控制和数据存储位置。 |

检测进程只返回原始测量、引擎版本、能力与错误信息。桌面程序负责规则判定、结果存储和复核。首版一个长驻检测实例串行推理，进程异常时保留已提交进度并可续跑。Windows 与 macOS 使用相同的消息契约，按实际引擎及其版本各自校准规则。若百度无法交付 macOS 检测引擎，需先确认检测引擎选型，再评估全部指标的覆盖、数值语义及校准，通过后才开放 macOS 本机检测。 [Oracle JDK 21 打包说明](https://docs.oracle.com/en/java/javase/21/jpackage/packaging-overview.html)

## Windows SDK 接入与授权验证

Java 接口和返回类型以随包《人脸识别 JAVA 离线 SDK 用户接入文档》第 8、9 章及 `src/com/jni/face/Face.java` 为准。公开的 WIN-C++-SDK 文档可对照能力和授权流程。 [百度 WIN-C++-SDK 文档](https://cloud.baidu.com/doc/FACE/s/Ol0rre5u5)

1. 使用 x64 JDK 编译包内 Java 示例。本机已用 Temurin 11.0.28 x64 编译通过。以 SDK 根目录为工作目录，将配套 OpenCV JAR 加入 classpath，将原生 DLL 目录加入 `java.library.path` 和进程 `PATH`。保留随包模型和 OpenCV 版本。 [Windows SDK 常见问题](https://cloud.baidu.com/doc/FACE/s/Eldlceb0k)
2. 将独立 `License.zip` 中的两个文件放入 SDK 根目录的 `license`。启动时调用 `sdkInit` 和 `isAuth()`，确认初始化返回 0 且授权为 `true` 后处理文件，进程结束时调用 `sdkDestroy()`。**实测记录**。在工作区使用默认根目录，以及在纯英文临时路径显式传入 SDK 根目录，两次均执行到 JNI 初始化，返回 `-1022`（`NETWORK_ERROR`），`isAuth()` 为 `false`，未进入样图检测。该结果只表明当前环境未能完成初始化，授权绑定和有效期尚无法确认。
3. 在实际运行工具的电脑上用包内 `LicenseTool.exe` 或 `Face.getDeviceId()` 获取硬件指纹，对照控制台的签发记录和有效期。若授权与目标设备不匹配，按控制台流程获取对应指纹的离线授权。替换后先验证初始化，再断开目标机外网验证同一授权可用。 [百度离线识别控制台](https://console.bce.baidu.com/ai/?fromai=1#/ai/face/offline/index) · [Windows SDK 常见问题](https://cloud.baidu.com/doc/FACE/s/Eldlceb0k)
4. 用 `Files.readAllBytes` 读取中文路径，再用配套 OpenCV 将字节解码成 `Mat`，保持预览与检测的图片方向一致。调用 `Face.detect(matAddr, 0)` 处理可见光图，使用 `FaceBox[]` 统计人数与原图像素尺寸。将随包 `conf` 复制为生效目录 `config`，用 `detect.json` 的 `max_detect_num` 显式开启多人脸检测，并用双人图确认。检测最小尺寸须低于业务合格尺寸，便于区分“脸太小”和“未检测到人脸”。逐张释放 `Mat` 和字节容器。
5. 对检出单脸的原图调用 `faceHeadPose`、`faceBlur`、`faceOcclusion`、`faceIllumination`。Java 接口以数组返回结果，需核对数组长度、数值与异常。用已知空白图、坏图和正常图确认 `detect` 的空值表现。健康检查通过后，才将已验证的无脸返回映射为“未检测到人脸”。单脸检测成功但质量数组为空时，将相应指标记为缺失。Java 手册给出光照接口返回 `float[]`、分值范围 0–1，需用明暗对照样图确认实测量程与分布。

## 判定规则与结果展示

以下参数用于现有百度 Windows SDK 试跑和人工校准。生产规则按实际引擎和版本，结合现网采集配置与样图校准后保存为版本化配置。

| 检查项 | 初始通过条件或取值方式 | 原因示例 |
| --- | --- | --- |
| 人脸数量 | `detect` 成功且恰好检出 1 张脸。按实包确认无脸返回，未知错误进入检测失败。 | 未检测到人脸、检测到多张人脸 |
| 人脸尺寸 | 原图中人脸框宽、高均 ≥ 100 px。100 px 是本项目试验起点，检测门槛独立配置。 | 人脸太小，宽 76 px，要求 ≥ 100 px |
| 人脸完整性 | 用原图坐标检查脸框越界，结合样图评估关键点越界及贴边。仅贴边先列待复核，证据充分的出画才计不合格。 | 人脸框越过右边界、脸部贴边需复核 |
| 姿态 | `abs(yaw)`、`abs(pitch)`、`abs(roll)` 各 ≤ 15°，以公开 Windows 文档推荐范围作为起点。 | 左右偏转 28°，上限 15° |
| 清晰度 | `faceBlur` ≤ 0.60，先按离线文档推荐值试跑。 | 模糊度 0.74，上限 0.60 |
| 局部遮挡 | 双眼、鼻、口、双颊、下巴各 ≤ 0.60，试跑后按部位校准。 | 左眼遮挡 0.81，上限 0.60 |
| 光照 | 实测确认 Java 手册描述的量程与方向后，以 `faceIllumination` ≥ 0.60 作为试跑条件，按现场图校准。逆光、局部高光或脸部阴阳光若需单独归因，用人脸区域亮度分布及局部对比度做辅助规则。 | 面部偏暗、脸部高光需复核 |

姿态、模糊度、遮挡、光照的起点取自随包 Java 手册第 9.12 节。比较符号、尺寸、完整性及启用条件由本项目配置。

- **合格**。所有必检项均取得有效值且通过。
- **不合格**。存在已确认的不合格项，展示所有可可靠测得的原因。无脸或多脸时到数量规则为止，细项标记为未执行。
- **待复核**。无确证的不合格项，但存在贴边、临界结果或必检指标缺失。标明缺失或触发复核的具体项目。
- **检测失败**。文件打不开、解码失败或 SDK 异常导致无法作出有效判断。保留失败阶段和错误码。发现授权或模型整体不可用时暂停批次并提示修复。

首版保留文件名中的 `live` 和 `rec` 字段用于对照。若需要补跑单张 RGB 静默活体，将分值独立展示，按同版本同配置验证可比性。原机若使用红外、深度或多帧活体，复现需对应输入和当时的配置。

## 批量工作流与交付形式

1. **扫描和检测。** 选择根目录后递归扫描 JPEG，保持相对路径和日期信息。启动前检查授权与必需能力，逐张测量并写入本地结果库。界面显示进度、已完成数量和异常。取消后可继续，按相对路径、文件内容标识及 SDK、模型、检测配置版本校验能否复用已有结果。仅调整应用判定阈值时，可用已保存的原始指标重新判定。
2. **筛选与复核。** 展示每张缩略图、状态及原因，支持按日期、状态和失败原因筛选。详情展示原图、人脸框、各项分值、阈值和原始抓拍记录。概览分别统计照片状态和各原因命中数，同一张图命中多个原因时各计一次。
3. **导出。** 提供 UTF-8 CSV 明细和按日期、原因汇总。明细包含相对路径、原图尺寸、原始抓拍字段、检测结果、所有原因、原始数值、规则版本、引擎标识和版本、异常码。用户复核意见单独保存，便于比较自动判定及人工结论。读取、推理和结果均留在本机，默认只读访问原图，日志和导出不包含授权内容。

## 实施顺序与验收

正式验收统一在 Windows x64 目标电脑上进行，覆盖离线授权、全量检测、人工复核和 CSV 导出。

| 阶段 | 验证内容 | 通过条件 |
| --- | --- | --- |
| Java 桌面 | 在 Windows 构建安装包，校验界面、目录访问、SQLite 和 CSV。 | Windows 界面符合原型，检测进程按协议运行。 |
| SDK 可用性 | 用包内 Java 示例在目标电脑验证初始化和断网静态图调用。取约 20–30 张现场样图，加已知无脸、双脸和损坏文件，检查返回值、脸框和原始质量值。 | 断网可授权并完成检测，中文目录可读。无脸、双脸、坏图有可复现的不同结果。必检能力能返回有效值，尤其确认光照量程。 |
| 质量校准 | 从各日期及不同光照、姿态中取约 150–250 张，由现场人员标注合格与原因。补入少量确认质量合格、来源明确的正常抓拍。同一次连续抓拍尽量分到同一组，划出独立验证集。 | 根据人工标注确定阈值和复核区间，在留出样本记录误放、误拦、待复核比例及各原因命中情况，逐项复查误判后锁定首版规则。 |
| 全量验收 | 在 Windows 断网状态下按规则配置跑完当前 4,022 张并导出 CSV。抽查异常、临界及高频原因，测试取消续跑和同配置重复运行。记录总耗时、单张耗时 P50/P95 和峰值内存。 | 文件与结果一一对应，四种状态合计为 4,022。已确认的质量问题都有逐图原因和证据，失败项可定位，复跑状态可复现，导出与界面数量一致。 |

先在 Windows 目标机验证断网初始化和静态照片质量字段，再完成样本校准与全量验收。MacBook 的安装和引擎验证随未来适配工作安排。
