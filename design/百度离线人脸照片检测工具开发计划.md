# 百度离线人脸照片检测工具开发计划

2026 年 11 月 17 日 · Windows x64 首版

## 1. 目标与实现依据

交付可在 Windows x64 断网环境运行的 JavaFX 桌面工具。用户可选择抓拍目录，批量检测 JPEG 静态照片的人脸数量、尺寸、完整性、姿态、清晰度、遮挡和光照，查看原图与检测证据，保存人工复核意见并导出 CSV。自动结论用于评估照片是否适合后续人脸识别，抓拍状态、`rec` 和 `live` 作为排查字段保留。macOS、本机网页版、局域网版、活体复测、身份比对、底库管理及历史未识别归因留待后续。

详细设计是正式行为、数据和接口的实现基准。总体方案提供目标机授权、现场样本和校准依据，HTML 原型提供布局、控件文案和操作路径。首开无历史时显示空状态，选择有历史批次的目录时恢复最近批次。分页按可见行数计算，日期取最近的合法祖先目录，检测结果来自本地 Worker。原型的内置样本、模拟授权和浏览器目录选择器用于研发演示。

## 3. 开发任务与阶段验收

### 阶段 0 · 工程骨架与测试数据

- [x] 建立 Maven 聚合工程，划分 `desktop`、`core`、`detector-protocol`、`detector-baidu-windows`。固定构建所用 JDK、JavaFX、SQLite JDBC 和 JSON 库版本。桌面端使用 Java 21 和 JavaFX 21，协议和 Windows Worker 以 Java 11 字节码为基线，百度 JNI 与 OpenCV 依赖由 Windows Worker 装配。
- [x] 固化 `initialize`、`measure`、`shutdown` 的 UTF-8 JSON Lines 请求与响应样例。覆盖成功测量、单项缺失、逐图错误、批次错误及协议版本校验。用可控的替身进程提供正常、迟到、重复、超时和异常退出的响应。
- [x] 建立测试输入清单。现有 `FaceCapture` 按 2026-11-10 至 2026-11-17 共 8 天、4,022 张 JPEG 作为现场全量基线。单独准备已知结果的对照输入，包含无脸、双脸、小脸、贴边、明暗、损坏 JPEG 及 EXIF 旋转和镜像。

验收通过条件为多模块可构建，Java 21 父进程可启动 Java 11 替身并完成三种操作，协议样例可重复使用。

2026-11-17 完成阶段 0 验收。Maven 离线 `clean verify` 通过，13 项协议测试通过。JavaFX 初始窗口及 SQLite 原生查询通过冒烟检查。见 [构建与启动说明](../README.md)、[协议样例](protocol-v1.jsonl) 和 [测试输入清单](测试输入清单.md)。真实百度 JNI 装配与离线授权验证进入阶段 1。

### 阶段 1 · 目标机 SDK 与 Windows Worker

- [ ] 使用包内示例在实际部署的 Windows x64 电脑上验证 Java 11 x64、DLL、OpenCV 3.2、模型、VC++ 依赖和 `conf` 部署至 `config` 后的实际生效情况。按目标机指纹核对离线授权的绑定和有效期，再断开外网验证 `sdkInit == 0`、`isAuth() == true` 及单脸、无脸探针。
- [ ] 在约 20–30 张现场照片及对照输入上记录返回值和错误码。确认无脸与解码失败的返回语义、多脸检出、低于 100 px 的小脸检出、脸框位置和裁剪行为、四项质量接口的字段与数组基数，尤其是光照量程和明暗方向。记录 `max_detect_num`、`min_face_size` 等实际生效配置。
- [ ] 实现 Worker 的中文路径读图、对实际解码字节计算 SHA-256、EXIF 方向归一化及原始／归一化尺寸记录。将中心点脸框转换成未裁剪的浮点左上坐标和宽高，保留置信度。单脸时返回质量指标和具体缺失项。启动返回引擎身份、指标语义版本和测量配置指纹，正常退出时释放图片资源并调用 `sdkDestroy()`。
- [ ] 实现独立 Java 11 进程的启动、串行派发、双路日志读取、帧和请求关联、超时回收及重启。目标机核对 DLL 日志与 stdout JSON 行的隔离，有交错则处理日志句柄后复验。初始化、逐图调用、取消回收和退出先按详细设计分别试用 60、30、2、5 秒，再依据目标机实测调整。
- [ ] 验证故障分级。能力或授权故障暂停批次，隔离的照片级故障落逐图结果，单项缺失进入质量规则。进程异常回收后重新探针并重试当前图一次，按独立探针及连续不同照片的故障表现判定逐图失败或暂停批次。

验收通过条件为目标机断网授权和探针通过，测试矩阵可复现且关键指标语义明确，Worker 可按协议测量和退出。既有初始化记录为 `-1022 (NETWORK_ERROR)` 且 `isAuth()` 为 `false`，目标机离线授权目前待验证。若暂未通过，保留实测记录、继续替身联调，待授权和指标验证通过后进入生产规则校准。

### 阶段 2 · 业务、结果库和导出

- [x] 实现只读递归扫描、中文路径、大小写不敏感扩展名和稳定排序。跳过符号链接与目录联接点，校验最终路径位于根目录内，统计不可读目录。独立验证日期、时间、原始状态、`rec` 和 `live`，保留无日期和字段缺失的照片。
- [x] 按详细设计 §7 建立 SQLite 迁移和索引。实现单实例文件锁、WAL、外键、单写队列、独立读连接和迁移前一致备份。存储扫描清单、内容版本、测量配置、规则版本、追加测量、判定原因和人工复核。
- [x] 实现就绪、启动检查、检测、取消、续跑、暂停重试和重新检测。每张照片的测量、判定和完成状态在同一事务提交，进度随提交刷新。重启归还未提交条目，过滤旧进程及重复回包。续跑沿用原清单，以内容 SHA-256 与测量配置指纹确定复用，内容替换或配置变更项重新测量，删除项保留在清单并记录故障。重新检测全量重扫并建立新批次，新增文件随本次扫描纳入。
- [x] 实现纯 Java 判定和证据。无脸、多脸按数量规则输出，单脸汇总可靠的不合格原因、贴边、临界和缺失项。以原始数值比较，验收等于阈值的边界及原因去重。规则版本不可变，阈值变化在事务内重判当前批次的已保存测量。人工复核绑定内容版本，同字节复跑或重判仍可追溯，替换后的新内容从未复核开始。
- [x] 实现按日期、自动状态、原因代码和不区分大小写的文件名关键词组合查询。列表和当前筛选导出复用查询定义，状态和原因统计复用日期范围。导出按启动时读事务的快照生成照片明细、按日期汇总、按日期和原因汇总，支持当前筛选和全部已检测两种范围。验证 UTF-8 BOM、CRLF、CSV 转义、文本公式防护、数值零与空值区分、导出失败时保留原目标文件。

验收通过条件为替身端到端跑通目录至 CSV 的流程。用同路径换图、删除文件、变更配置、杀进程后恢复、重复回包、数据库写入失败及检测中重判验证一致性。统计与导出只读取已提交数据，原 JPEG 保持只读。

2026-11-18 阶段 2 通过替身验收。9 项业务回归通过，4,022 张只读业务替身清单、SQLite 提交与 CSV 汇总一致。其余阶段的实施结果与目标机待验收项见 [自动接续开发验收记录](自动接续开发验收记录.md)。

### 阶段 3 · JavaFX 界面与原图预览

- [ ] 用 FXML、CSS 和 ViewModel 实现日期导航、目录和进度、五张统计卡片、结果列表及右栏详情。验证切换日期保留状态和搜索词、清空原因筛选并返回第一页，列表支持详情联动和跨页上一张／下一张。
- [ ] 实现按目标像素解码和有上限的缩略图缓存。背景任务读取图像和核对哈希，按 EXIF 方向和等比居中变换对齐人脸框。原图已变更或不可读时给出提示并隐藏旧框。切换目录、筛选和选中项时丢弃迟到的查询或预览结果。
- [ ] 实现检测设置、人工复核、原因统计、导出 CSV 四个弹窗。检查默认值回填后提交、重判刷新、复核备注上限 300 字、清除意见、同照片同原因只计一次，以及系统目录和保存对话框的操作。人工结论单独呈现，状态统计保持自动检测口径。
- [ ] 检查中文界面、空目录或不可读目录、授权故障、无引擎时的历史结果查看和导出，以及检测与取消期间的交互。目录扫描、解码、数据库和进程调用在后台执行，界面操作由 JavaFX Application Thread 刷新。

验收通过条件为在 Windows 上按原型走通主窗口和四个弹窗，核对键盘焦点、窗口变窄及显示缩放。用真实 Worker 复查旋转、镜像、框开关、原图替换、检测暂停重试、检测中复核与导出。正式首开显示未选目录和空列表，替身仅用于开发和测试。

### 阶段 4 · 质量校准与规则锁定

- [ ] 从各日期、光照、姿态及故障类型抽取约 150–250 张，补入来源和质量已确认的正常抓拍。由现场人员标注质量结论及原因，将相近连续抓拍放入同一分组，再划分校准集和留出验证集。
- [ ] 用阶段 1 验证过的真实 Worker 跑原始测量。以宽高 100 px、姿态角绝对值 15°、模糊度与七部位遮挡上限 0.60 作为初始试跑值。待实测确认光照量程和方向后试跑光照下限 0.60。结合框裁剪行为和样图定义出画证据、贴边和临界复核区间。
- [ ] 在留出集记录样本分母、误放、误拦、待复核比例和各原因命中情况，复查典型误判。现场确认后冻结生产规则版本和 SDK 生效配置，保存样本分组、标注、校准记录、引擎版本、指标语义版本和测量配置指纹。

验收通过条件为真实测量、规则配置和人工标注可追溯，现场确认首版结论及复核口径。质量通过线由现场在校准时确认。

- [ ] 用冻结规则跑完现有 4,022 张，核对扫描清单每张恰有一个当前提交结果，四种自动状态合计为 4,022。抽查异常、临界值、高频原因和人工复核。核对两种导出范围、三类 CSV 与界面统计，复验取消后继续、程序重启、规则重判、同配置重复运行和复核保留。
- [ ] 记录目标机环境、总耗时、单张耗时 P50／P95、桌面端与 Worker 峰值内存及异常清单。交付应用镜像、安装包、部署与使用说明、生产规则和 SDK 配置标识、校准记录、全量验收报告及三类 CSV。发布记录同时列出应用版本、规则版本、测量配置指纹和目标机验收结果。
