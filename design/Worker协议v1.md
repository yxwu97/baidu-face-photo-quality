# Worker 协议 v1

详细设计 §5.2 和 §5.3 定义运行约束。[protocol-v1.jsonl](protocol-v1.jsonl)按请求、响应交替排列，编号用于引用样例。跨 JVM 测试从该文件加载数据。

## 帧与操作

- stdin 和 stdout 按 UTF-8 无 BOM 传输。每行一个 JSON 对象，发送后刷新。诊断日志走 stderr。
- 请求和响应均包含整数协议版本 `v`、通道 `face.worker`、非空字符串 `id` 及 `op`。v1 的 `v` 固定为 1。规范的版本拒绝帧使用 Worker 支持的版本，并回传原请求编号与操作。父进程对不支援的响应版本按协议错误处理。
- 请求包含对象 `args`。成功响应包含 `ok: true` 和对象 `data`，失败响应包含 `ok: false` 和对象 `error`。

| 操作 | 参数 | 响应 |
| --- | --- | --- |
| `initialize` | `configurationId` 为本次运行配置标识 | 引擎标识和版本、测量配置指纹、指标语义版本、授权状态、探针结果和能力列表 |
| `measure` | `path` 为图片绝对路径 | 原始字节 SHA-256、方向和尺寸、脸框及数量、指标、缺失原因和耗时 |
| `shutdown` | 空对象 | 释放状态，发出响应后正常退出 |

## 指标与故障

- 尺寸和脸框以归一化图像为基准，脸框保留未裁剪的浮点像素坐标。图像字段同时保留解码原始宽高和 EXIF 方向。单脸缺测字段写 `null`，在 `missing` 中记录 `field` 和 `reason`。数值须为有限值。
- 错误字段包括 `scope`、`stage`、`code` 和 `retryable`。可附整数 `nativeCode`。已读入但解码失败的文件可附 `sha256`。`file` 代表照片级错误，`batch` 代表批次级错误。进程级错误由父进程识别。
- 帧解析拒绝重复字段、非法 JSON 和单行多个对象；信封校验拒绝无效版本、通道、操作、请求参数形状及错误结构。尺寸和指标的业务语义须经阶段 1 的真实 Worker 验证。
- 响应与请求按编号和操作关联。样例中的替身授权字段、哈希和测量值为测试常量。

测试替身启动模式为 `NORMAL`、`MISSING_METRIC`、`FILE_ERROR`、`BATCH_ERROR`、`LATE`、`DUPLICATE`、`TIMEOUT` 和 `EXIT`。测试进程用于复现迟到、重复、挂起和退出，生产进程回收与重试在阶段 1 实现。
